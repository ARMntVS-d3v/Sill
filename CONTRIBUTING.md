# Contributing to Sill

Thanks for stopping by. The whole point of Sill is that adding a widget is easy —
if you hit friction, that's a bug in the project, please open an issue.

## Dev setup

```bash
brew install xcodegen
git clone https://github.com/ARMntVS-d3v/Sill.git
cd Sill
make run
```

- `project.yml` is the source of truth; `Sill.xcodeproj` is generated by xcodegen
  (and committed so the repo opens in Xcode without extra steps).
- `make run` builds into `~/Library/Caches/sill-build` and launches the app via
  `open` — launching the binary directly breaks macOS permission prompts
  (the terminal becomes the "responsible process" for TCC).
- `make logs` streams the app's log. Launched via `open`, stdout goes nowhere.

## Add your own widget

One file in `Widgets/`, one line in `Core/WidgetRegistry.swift`:

```swift
import SwiftUI

@MainActor @Observable
final class HelloWidget: Widget {
    static let descriptor = WidgetDescriptor(
        id: "hello", name: "Hello", icon: "hand.wave",
        sizes: [.small], defaultSize: .small)

    private let context: WidgetContext
    init(context: WidgetContext) { self.context = context }

    var body: AnyView { AnyView(Text("Hello!").font(TileFont.title)) }
}
```

The shell hands every widget a `WidgetContext` — tile size, theme tokens, disk
cache, per-tile settings, a scheduler — and the lifecycle does the rest:

- `activate()` is called when the panel opens, `deactivate()` when it closes.
  A closed panel means a sleeping widget: **no timers, no polling in the
  background**. The idle target for the whole app is ≈0% CPU.
- Subscribe to change notifications where the system offers them (EventKit,
  NSWorkspace…); poll on a timer only where it doesn't.
- `refresh()` — show cache first, update after. No spinners on open.
- A slow or crashing widget must not stall the panel or its neighbors.

## Rules that reviews actually enforce

Read `docs/standards.md` before laying out a tile. The short version:

- Fonts only from `TileFont`, icon sizes only from `TileIcon`, spacing from
  `TileMetrics`. A number that isn't in `docs/standards.md` doesn't go in code.
- Colors only from theme tokens. Hardcoded color in a widget fails review;
  the one exception is text over artwork.
- Empty states use `TilePlaceholder` and the shared vocabulary ("No events",
  "Nothing playing"…). No custom phrasing for the same meaning.
- Interactive elements inside a tile are marked `.tileControl()` — otherwise
  the tile drags out from under the cursor in edit mode.
- Sizes follow one principle: square = one number and one action, rectangle =
  plus context, large = plus history and every action. The type size never
  changes between tile sizes — the amount shown does.

Pre-flight checks:

```bash
grep -rn "\.font(\.system(" Widgets/ Shell/     # must be empty
grep -rn "minimumScaleFactor" Widgets/          # must be empty
```

## Themes

A theme is a JSON file of tokens — no Swift needed. Built-in themes live in
`Resources/Themes/`, user themes in `~/.config/sill/themes/` with hot-reload.
New themes are welcome as PRs.

## Pull requests

- Code, comments, and UI strings are English; UI strings get Russian
  translations in `Resources/Localizable.xcstrings` (or note in the PR that
  they need one).
- CI builds with xcodebuild on every PR; make sure `make build` passes locally.
- One change per PR. Screenshots for anything visual — `kill -USR2 <pid>`
  writes a panel snapshot to `/tmp/sill_panel.png` in Debug builds.
